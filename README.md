# אוטומציית התראות על שינוי סטטוס ליד — Surense CRM

מימוש של `automation-plan.md`: סריקה שעתית של Surense CRM לאיתור לידים שהסטטוס שלהם השתנה, ושליחת הודעה למקור המפנה — ראשון עד שישי.

**מצב נוכחי: `dryRun = true`.** המערכת סורקת ומדווחת מה *היה* נשלח, ולא שולחת דבר. זה שלב 1 בתוכנית ההפעלה המדורגת (סעיף 9).

---

## למה Apps Script ולא משימה מתוזמנת של Claude בענן

החלטה #2 בתוכנית הייתה "משימה מתוזמנת של Claude בענן". **זה לא יעבוד**, ונבדק בפועל: מסביבת ההרצה של Claude בענן, גם `api.surense.com` וגם `docs.google.com` חסומים ב-proxy (403). סוכן שרץ שם לא יכול להגיע לא ל-CRM ולא לגיליונות.

Google Apps Script פותר בדיוק את זה — הוא רץ **בתוך** Google:

| צורך | ב-Apps Script |
|---|---|
| קריאה ל-Surense API | `UrlFetchApp` — יוצא לאינטרנט בלי חסימה |
| קריאה/כתיבה לגיליונות | `SpreadsheetApp` — גישה מקומית, בלי API keys |
| תזמון שעתי | טריגר מובנה בפלטפורמה |
| שליחת מייל | `MailApp` (ראה הערה על Outlook למטה) |
| סודות | Script Properties |

בנוסף: אין שרת להחזיק, אין Service Account, ואין מפתח JSON לנהל.

## מה חוסם הפעלה אמיתית

חמישה דברים חסרים. הקוד בנוי ומלא, אבל בלעדיהם הוא לא יכול לשלוח:

| # | חסר | למה זה חוסם |
|---|---|---|
| 1 | **`SURENSE_CLIENT_SECRET`** | בלעדיו אין טוקן, אין קריאה ל-API. בתוכנית מסומן כ"נחשף בצ'אט — לסובב". **סובב אותו ב-Surense ואל תשלח לי אותו** — הוא נכנס ישירות ל-Script Properties |
| 2 | **גיליון המיפוי** (`SHEET_URL_SOURCES`) | לפי סעיף 3: 3,255 לידים, **אפס כתובות מייל**. בלי מיפוי מקור←מייל אין למי לשלוח |
| 3 | **תיבת Outlook השולחת** | קונקטור Microsoft 365 מופיע כלא מחובר בסשן הזה. ראה "הערה על Outlook" למטה |
| 4 | **נוסחי 34 הסטטוסים הנותרים** | לא חוסם ריצה — הם פשוט שקטים לפי ברירת המחדל |
| 5 | **נוסח החתימה** | `EMAIL_SIGNATURE` ב-`Notify.gs` הוא מציין מקום |

### לגבי הגיליון שנתת

הקישור ששלחת (`1Omrb0-...`) **אינו** גיליון הלידים שבתוכנית — שם רשום `1_fkaCM7H7N7bouSwk-pS7B5cvqE0P9uf`.

לכן הנחתי ש-`1Omrb0-...` הוא **חוברת העבודה של האוטומציה**, זו שמחזיקה את הלשוניות `מיפוי`, `מצב` ו-`יומן`. הן ייווצרו אוטומטית בריצה הראשונה. אם התכוונת למשהו אחר — `CONFIG.workbookId` ב-`Config.gs`, שורה אחת.

שים לב שהאוטומציה **לא קוראת מגיליון הלידים בכלל** — היא קוראת ישירות מ-Surense API, כמו שסעיף 7 מגדיר. הגיליון הוא ייצוא, לא מקור אמת.

### הערה על Outlook

Apps Script שולח דרך Gmail, לא Outlook. `Notify.gs` מכיל את `sendViaGraph_()` — מימוש מלא של שליחה דרך Microsoft Graph, מוכן אבל **לא מחובר בכוונה**: התוכנית עוד לא קובעת מאיזו תיבה שולחים (שאלה פתוחה #3), ולבחור בעצמי זה ניחוש. כשתחליט — מחליפים קריאה אחת ב-`sendEmail_()`.

## התקנה

1. פתח את חוברת העבודה → **Extensions → Apps Script**
2. העתק את **[`dist/Code.gs`](dist/Code.gs)** — כל הקוד בקובץ אחד — לתוך `Code.gs` שנוצר אוטומטית, במקום התוכן הקיים.

   <details>
   <summary>או, אם אתה מעדיף קובץ לכל מודול</summary>

   צור קובץ לכל אחד מ-`apps-script/`:

   | קובץ | תפקיד |
   |---|---|
   | `Config.gs` | הגדרות — מזהי גיליונות, לוח זמנים, בלם ההצפה |
   | `Statuses.gs` | **טבלת סטטוס ← נוסח** (סעיף 5) |
   | `Surense.gs` | OAuth + חיפוש לידים עם pagination |
   | `Sheets.gs` | מיפוי מקורות, טבלת מצב, חותמת זמן |
   | `Notify.gs` | הרכבת המייל ושליחתו |
   | `Main.gs` | אלגוריתם הריצה (סעיף 7) |
   | `Triggers.gs` | התקנת הטריגר + `checkSetup()` |
   | `Log.gs` | יומן ריצה |

   `dist/Code.gs` נבנה מהם אוטומטית: `python3 scripts/bundle.py`
   </details>

3. **Project Settings** → סמן *Show `appsscript.json`* והדבק את התוכן מהתיקייה
   (קובע `Asia/Jerusalem` — קריטי לבדיקת יום בשבוע)
4. **Project Settings → Script Properties** — הוסף:

   | Property | ערך |
   |---|---|
   | `SURENSE_CLIENT_ID` | `cid_NpUMsHGD80q0izlhEQnfoA` |
   | `SURENSE_CLIENT_SECRET` | הסוד **אחרי סיבוב** |

   > הסודות נמצאים כאן ולא בקוד. אין שום סוד ב-repo הזה.

5. ב-`Config.gs` מלא את `operatorEmail` — לשם הולכות התראות בלם ההצפה
6. הרץ `checkSetup()` — מאמת סודות, מיפוי ואימות מול Surense
7. הרץ `dryRun()` ובדוק את לשונית `יומן`
8. רק אחרי שהדוח נראה נכון: `CONFIG.dryRun = false` ואז `installHourlyTrigger()`

## איך התזמון עובד

Apps Script **לא** מאפשר טריגר שעתי המוגבל לימים מסוימים. לכן הטריגר יורה כל שעה כל יום, ו-`hourlyUpdate()` יוצא מיד בשבת. לשינוי — `Config.gs`:

```js
activeDays:  [0, 1, 2, 3, 4, 5],   // 0 = ראשון ... 6 = שבת
activeHours: null,                  // null = כל השעות
```

> Google מריץ טריגרים שעתיים בתוך חלון של כשעה, לא בדקה עגולה.

## מנגנוני ההגנה

שלושת אלה הם הסיבה שאפשר להפעיל את זה בלי לחשוש. כולם מכוסים בבדיקות.

**רשימה סגורה** — סטטוס שאינו ב-`SEND_ON_STATUS` לא שולח כלום. 34 הסטטוסים שטרם הוגדרו שקטים אוטומטית, בלי צורך לרשום אותם.

**בלם הצפה** — יותר מ-25 הודעות בריצה אחת: הכול נעצר, אף הודעה לא יוצאת, ואתה מקבל התראה אחת. חותמת הזמן **לא** מתקדמת, כך שאחרי בדיקה ידנית אפשר לרוץ שוב על אותו חלון.

**מניעת כפילויות** — לשונית `מצב` שומרת את הסטטוס האחרון שדווח לכל ליד. הודעה יוצאת רק כש`סטטוס נוכחי ≠ סטטוס אחרון שדווח`, כך שריצה כפולה לא שולחת פעמיים.

בנוסף: ריצה שנכשלה **לא** מקדמת את חותמת הזמן — אותם לידים ייסרקו שוב בשעה הבאה במקום ללכת לאיבוד. נעילה מונעת שתי ריצות במקביל.

### התאמת שמות מקורות

סעיף 6 מזהה את זה כנקודת הכשל מספר 1, בצדק. `normalizeText_()` מנרמל רווחים כפולים, גרשיים טיפוגרפיים (`״` `"` `׳` `'`) ותווי כיווניות נסתרים — לפני כל השוואה, בשני הצדדים. מקור שלא נמצא נרשם ביומן עם שמו המדויק.

זה מטפל גם ב-950 הלידים שמקורם קטגוריה (`קמפיין`, `חבר מביא חבר`): אין להם שורת מיפוי, אז הם מדולגים בשקט ונספרים כ"ממתין" — בדיוק כפי שהתוכנית מגדירה.

## פונקציות תפעול

| פונקציה | מה היא עושה |
|---|---|
| `checkSetup()` | מאמת סודות, מיפוי ואימות מול Surense |
| `dryRun()` | סריקה מלאה בלי לשלוח — שלב 1 |
| `runNow()` | ריצה ידנית, בלי בדיקת לוח זמנים |
| `installHourlyTrigger()` | הפעלת התזמון |
| `removeTriggers()` | עצירה מלאה |
| `listTriggers()` | בדיקה שהטריגר חי |
| `resetWatermark()` | סריקה מחדש של חלון הזמן האחרון |

## בדיקות

```bash
node test/run.js            # מול המודולים ב-apps-script/
node test/run.js --bundle   # מול dist/Code.gs — מה שבאמת מודבק לעורך
```

36 בדיקות שמריצות את קוד ה-`.gs` האמיתי מול stubs של Apps Script — בלי לגעת ב-Surense או בגיליון. מכוסים: סינון ימים לפי אזור זמן, הרשימה הסגורה, נרמול שמות, מניעת כפילויות, pagination, בלם ההצפה, ושמירת חותמת הזמן בכישלון.

הרצת `--bundle` תופסת bundle מיושן או סדר שרשור שבור לפני שהם מגיעים לעורך.
