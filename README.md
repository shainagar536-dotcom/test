# אוטומציות Surense CRM ← Google Sheets

שתי אוטומציות עצמאיות באותו פרויקט Apps Script. אפשר להפעיל כל אחת בנפרד; אף אחת לא תלויה בשנייה.

| אוטומציה | מה היא עושה | מצב |
|---|---|---|
| **מראה** (`hourlyMirror`) | מעתיקה את כל הלידים מה-CRM ללשונית בגיליון, כל שעה | מוכן להרצה |
| **מתריע** (`hourlyUpdate`) | שולח מייל למקור המפנה כשסטטוס ליד משתנה | `dryRun = true` |

**המתריע נמצא ב-`dryRun`** — סורק ומדווח מה *היה* נשלח, ולא שולח דבר. זה שלב 1 בתוכנית ההפעלה המדורגת (סעיף 9 ב-`automation-plan.md`).

---

## המראה: העתק של ה-CRM בגיליון

כל ריצה **מחליפה** את תוכן הלשונית במלואו במקום לתקן שורות. החלפה מלאה מרפאת את עצמה: ליד שנמחק ב-CRM נעלם, שדה שהשתנה פשוט נכון שוב, ואין הצטברות של סטיות. המחיר הוא קריאה מחדש של הכול בכל שעה — בכמה אלפי לידים זה הרבה בתוך מה ש-Apps Script מרשה.

**העמודות מגיעות מה-CRM עצמו.** הקוד קורא ל-`/leads/fields` ובונה מהן את הכותרות, אז שדה שתוסיף ב-Surense יופיע בגיליון בלי שינוי קוד. אם אתה רוצה תת-קבוצה במקום הכול — `CONFIG.mirror.columns`.

### שלושה מקרים שבהם המראה **לא** כותבת

זה מכוון, וזה מה שמונע אובדן נתונים:

| מצב | מה קורה |
|---|---|
| הקריאה מה-CRM נקטעה באמצע | הגיליון לא נגע. כתיבה חלקית הייתה נראית כמו מחיקה המונית |
| ה-CRM החזיר אפס לידים | הגיליון לא נגע. כנראה תקלה, לא "תמחק הכול" |
| ריצה כבר רצה | דילוג. נעילה מונעת שתי כתיבות במקביל |

## "אילו לקוחות הצטרפו ואינם בגיליון?"

`reportMissingLeads()` — משווה את ה-CRM מול מה שיש בגיליון עכשיו, **בלי לגעת בו**, וכותב לשונית `דוח פערים` עם:

- לידים שקיימים ב-CRM וחסרים בגיליון
- שורות בגיליון שאין להן ליד תואם ב-CRM

**הרץ את זה לפני הסנכרון הראשון.** זה בדיוק מה שהמראה עומדת להוסיף ולמחוק — לפני שנוגעים בגיליון.

הפונקציה לא יודעת מראש איזו עמודה בגיליון מחזיקה את המזהה, אז היא **מגלה אותה**: כל עמודה מקבלת ציון לפי *שיעור* הערכים שלה שמופיעים כמזהים ב-CRM. עמודת שמות מקבלת ציון אפס גם בגיליון ארוך; עמודת מזהים מקבלת ציון גבוה גם בגיליון קצר או כזה שיש בו שורות ישנות.

> אחרי שהמראה תרוץ, השאלה הזו נעלמת מעצמה — הגיליון *הוא* ה-CRM, אז שום ליד לא יכול לחסר בו.

## למה Apps Script ולא משימה מתוזמנת של Claude בענן

החלטה #2 בתוכנית הייתה "משימה מתוזמנת של Claude בענן". **זה לא יעבוד**, ונבדק בפועל: מסביבת ההרצה של Claude בענן, גם `api.surense.com` וגם `docs.google.com` חסומים ב-proxy (403). סוכן שרץ שם לא יכול להגיע לא ל-CRM ולא לגיליונות.

Google Apps Script פותר בדיוק את זה — הוא רץ **בתוך** Google:

| צורך | ב-Apps Script |
|---|---|
| קריאה ל-Surense API | `UrlFetchApp` — יוצא לאינטרנט בלי חסימה |
| קריאה/כתיבה לגיליונות | `SpreadsheetApp` — גישה מקומית, בלי API keys |
| תזמון שעתי | טריגר מובנה בפלטפורמה |
| שליחת מייל | `MailApp` (ראה הערה על Outlook למטה) |
| סודות | Script Properties |

בנוסף: אין שרת להחזיק, אין Service Account, ואין מפתח JSON לנהל.

## מה חסר להפעלה

**למראה חסר דבר אחד בלבד:**

| חסר | למה |
|---|---|
| **`SURENSE_CLIENT_SECRET`** | בלעדיו אין טוקן ואין קריאה ל-API. הסוד נחשף בצ'אט ולכן **חייב סיבוב** ב-Surense לפני שימוש. הוא נכנס ישירות ל-Script Properties — לא לקוד, לא ל-git |

זהו. עם הסוד המסובב, המראה עובדת.

**למתריע חסר עוד, והוא לכן נשאר ב-`dryRun`:**

| חסר | למה זה חוסם |
|---|---|
| **גיליון המיפוי** (`SHEET_URL_SOURCES`) | לפי סעיף 3: 3,255 לידים, **אפס כתובות מייל**. בלי מיפוי מקור←מייל אין למי לשלוח |
| **תיבת Outlook השולחת** | קונקטור Microsoft 365 מופיע כלא מחובר. ראה "הערה על Outlook" למטה |
| **נוסחי 34 הסטטוסים** | לא חוסם ריצה — הם פשוט שקטים לפי ברירת המחדל |
| **נוסח החתימה** | `EMAIL_SIGNATURE` ב-`Notify.gs` הוא מציין מקום |

### לגבי הגיליון

הקישור ששלחת (`1Omrb0-...`) **אינו** גיליון הלידים שבתוכנית — שם רשום `1_fkaCM7H7N7bouSwk-pS7B5cvqE0P9uf`. הנחתי ש-`1Omrb0-...` הוא חוברת העבודה: לשונית `gid=737522327` מקבלת את המראה, והלשוניות `מיפוי`, `מצב`, `יומן` ו-`דוח פערים` נוצרות לצידה. אם התכוונת אחרת — `CONFIG.workbookId` ו-`CONFIG.mirror.sheetGid` ב-`Config.gs`.

מקור האמת הוא ה-CRM, לא הגיליון. שתי האוטומציות קוראות מ-Surense API ישירות.

### הערה על Outlook

Apps Script שולח דרך Gmail, לא Outlook. `Notify.gs` מכיל את `sendViaGraph_()` — מימוש מלא של שליחה דרך Microsoft Graph, מוכן אבל **לא מחובר בכוונה**: התוכנית עוד לא קובעת מאיזו תיבה שולחים (שאלה פתוחה #3), ולבחור בעצמי זה ניחוש. כשתחליט — מחליפים קריאה אחת ב-`sendEmail_()`.

## התקנה

1. פתח את חוברת העבודה → **Extensions → Apps Script**
2. העתק את **[`dist/Code.gs`](dist/Code.gs)** — כל הקוד בקובץ אחד — לתוך `Code.gs` שנוצר אוטומטית, במקום התוכן הקיים.

   <details>
   <summary>או, אם אתה מעדיף קובץ לכל מודול</summary>

   צור קובץ לכל אחד מ-`apps-script/`:

   | קובץ | תפקיד |
   |---|---|
   | `Config.gs` | הגדרות — מזהי גיליונות, לוח זמנים, בלם ההצפה |
   | `Statuses.gs` | **טבלת סטטוס ← נוסח** (סעיף 5) |
   | `Surense.gs` | OAuth, חיפוש לידים עם pagination, סכימת שדות |
   | `Mirror.gs` | סנכרון המראה + `previewApi()` |
   | `Diff.gs` | דוח פערים בין ה-CRM לגיליון |
   | `Sheets.gs` | מיפוי מקורות, טבלת מצב, חותמת זמן |
   | `Notify.gs` | הרכבת המייל ושליחתו |
   | `Main.gs` | אלגוריתם הריצה (סעיף 7) |
   | `Triggers.gs` | התקנת הטריגר + `checkSetup()` |
   | `Log.gs` | יומן ריצה |

   `dist/Code.gs` נבנה מהם אוטומטית: `python3 scripts/bundle.py`
   </details>

3. **Project Settings** → סמן *Show `appsscript.json`* והדבק את התוכן מהתיקייה
   (קובע `Asia/Jerusalem` — קריטי לבדיקת יום בשבוע)
4. **Project Settings → Script Properties** — הוסף:

   | Property | ערך |
   |---|---|
   | `SURENSE_CLIENT_ID` | `cid_NpUMsHGD80q0izlhEQnfoA` |
   | `SURENSE_CLIENT_SECRET` | הסוד **אחרי סיבוב** |

   > הסודות נמצאים כאן ולא בקוד. אין שום סוד ב-repo הזה.

5. הרץ `checkSetup()` — מאמת סודות, גישה לגיליון ואימות מול Surense

**להפעלת המראה:**

6. `previewApi()` — מדפיס את מבנה התשובות האמיתי של ה-API (ראה למטה)
7. `reportMissingLeads()` — בדוק את לשונית `דוח פערים`: זה מה שעומד להשתנות
8. `syncLeads()` — הסנכרון הראשון
9. `installMirrorTrigger()` — מכאן זה רץ לבד כל שעה

**להפעלת המתריע** (נפרד לגמרי, ודורש את גיליון המיפוי):

10. ב-`Config.gs` מלא את `operatorEmail` — לשם הולכות התראות בלם ההצפה
11. מלא את לשונית `מיפוי` בכתובות מייל
12. `dryRun()` → בדוק את לשונית `יומן` → `CONFIG.dryRun = false` → `installNotifierTrigger()`

### למה `previewApi()` חשוב

את ה-API לא היה אפשר לקרוא מהסביבה שבה הקוד נכתב — היא חסומה אליו. לכן שמות השדות ומבנה המעטפת של התשובות **לא אומתו מול תשובה אמיתית**. `previewApi()` מדפיס בדיוק מה ה-API מחזיר: אילו שדות יש, איך נראית המעטפת, ואיך נראה ליד אחד. אם משהו לא תואם — זה תיקון ב-`CONFIG.leadFields`, לא שינוי בלוגיקה.

## איך התזמון עובד

Apps Script **לא** מאפשר טריגר שעתי המוגבל לימים מסוימים. לכן הטריגר יורה כל שעה כל יום, ו-`hourlyUpdate()` יוצא מיד בשבת. לשינוי — `Config.gs`:

```js
activeDays:  [0, 1, 2, 3, 4, 5],   // 0 = ראשון ... 6 = שבת
activeHours: null,                  // null = כל השעות
```

> Google מריץ טריגרים שעתיים בתוך חלון של כשעה, לא בדקה עגולה.

## מנגנוני ההגנה

שלושת אלה הם הסיבה שאפשר להפעיל את זה בלי לחשוש. כולם מכוסים בבדיקות.

**רשימה סגורה** — סטטוס שאינו ב-`SEND_ON_STATUS` לא שולח כלום. 34 הסטטוסים שטרם הוגדרו שקטים אוטומטית, בלי צורך לרשום אותם.

**בלם הצפה** — יותר מ-25 הודעות בריצה אחת: הכול נעצר, אף הודעה לא יוצאת, ואתה מקבל התראה אחת. חותמת הזמן **לא** מתקדמת, כך שאחרי בדיקה ידנית אפשר לרוץ שוב על אותו חלון.

**מניעת כפילויות** — לשונית `מצב` שומרת את הסטטוס האחרון שדווח לכל ליד. הודעה יוצאת רק כש`סטטוס נוכחי ≠ סטטוס אחרון שדווח`, כך שריצה כפולה לא שולחת פעמיים.

בנוסף: ריצה שנכשלה **לא** מקדמת את חותמת הזמן — אותם לידים ייסרקו שוב בשעה הבאה במקום ללכת לאיבוד. נעילה מונעת שתי ריצות במקביל.

### התאמת שמות מקורות

סעיף 6 מזהה את זה כנקודת הכשל מספר 1, בצדק. `normalizeText_()` מנרמל רווחים כפולים, גרשיים טיפוגרפיים (`״` `"` `׳` `'`) ותווי כיווניות נסתרים — לפני כל השוואה, בשני הצדדים. מקור שלא נמצא נרשם ביומן עם שמו המדויק.

זה מטפל גם ב-950 הלידים שמקורם קטגוריה (`קמפיין`, `חבר מביא חבר`): אין להם שורת מיפוי, אז הם מדולגים בשקט ונספרים כ"ממתין" — בדיוק כפי שהתוכנית מגדירה.

## בדיקות

```bash
node test/run.js            # מול המודולים ב-apps-script/
node test/run.js --bundle   # מול dist/Code.gs — מה שבאמת מודבק לעורך
```

59 בדיקות שמריצות את קוד ה-`.gs` האמיתי מול stubs של Apps Script — בלי לגעת ב-Surense או בגיליון. מכוסים: סינון ימים לפי אזור זמן, הרשימה הסגורה, נרמול שמות, מניעת כפילויות, pagination, בלם ההצפה, שמירת חותמת הזמן בכישלון, החלפה מלאה של המראה, שלושת מקרי ההימנעות מכתיבה, שיטוח ערכים מקוננים, וגילוי עמודת המזהה.

הרצת `--bundle` תופסת bundle מיושן או סדר שרשור שבור לפני שהם מגיעים לעורך.
